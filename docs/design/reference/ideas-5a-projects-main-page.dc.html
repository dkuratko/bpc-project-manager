Notes — Projects list
What a row is
One row per project — a place. The value, margin and status columns describe its current version only, never a sum. A project priced three ways is one line worth $106,000, not three lines worth $281,200. Expanding shows the versions and their renditions; that is the only place several numbers appear together.
Why the five counters
Not a dashboard — five questions an estimator actually asks before lunch. Two of them are warnings (blocked bids, expiring quotes) because those are the failures that cost money quietly. Each counter is a filter: clicking “4 quotes expiring” filters the list to them.
Status is two fields, shown as one column
Project status (Open / Won / In progress / Complete / Lost) and the current rendition’s state (Draft / Sent / Locked). The column shows whichever is more urgent — “Draft · blocked” beats “Open”, because that is what needs doing.
Problems I see
· “No current version” is a real state and reads badly. BPCp 26-252 has two drafts and nothing issued, so Value shows the highest draft — which is a guess about the estimator’s intent. Better: show a dash and force them to mark one version current.
· Won projects still show a bid due date column that is meaningless, and Actuals — the thing that matters after winning — is not reachable from this list at all. Won work probably deserves its own saved view with different columns.
· Three flag glyphs will become eight. The moment there are separate flags for late COs, missing manifests and lapsed insurance, this column is unreadable. Cap it at three and put the rest in a hover.
· Estimator filter assumes ownership which the schema does not record yet.
