Notes — Services
The list column that matters is Method
It tells you how the quantity gets into the estimate: typed by the estimator (per unit), counted off a photo (visual), fixed (lump sum), or derived from a spec the component already carries (bound). Bound services are the ones that stop the catalog exploding into one service per product.
Rate validated is a real column, not a nicety
“11 rates never validated” means eleven numbers in this catalog are somebody’s guess from an unknown year. Actuals is what retires that filter, which is the argument for building Actuals sooner than it feels necessary.
Problems I see
· Interpolation is invisible in the list. A service rated on 6 of 12 specs looks complete here; only the preview reveals the gap. The list needs a coverage indicator, because an interpolated rate on a bid is a silent assumption.
· “Generates” is one value per service — but Remove Existing Footings produces both concrete debris and reusable base material on some jobs. One output per service will not survive contact.
· Modifiers overlap with the soil catalog — flagged in red here so the duplication is visible on screen, not just in a note. Delete the soil rows from modifier lists.
· Crew size lives on the service, factor lives on the profile. When a component requires a service, which crew wins? Undefined today.
